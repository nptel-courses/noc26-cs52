M01 – Course Overview & C++ Fundamentals

Concept 1.1 – Why C++? Evolution, Performance, and Multi‑Paradigm Power

📌 Definition

C++ is a general‑purpose programming language created by Bjarne Stroustrup as an extension of the C programming language, or "C with Classes". It provides low‑level memory manipulation (like C) combined with high‑level abstractions (classes, templates, lambdas) and supports multiple programming paradigms: procedural, object‑oriented, generic, and functional.

🧠 Encyclopedic Explanation

C++ occupies a unique position in the programming landscape. It is one of the few languages that can deliver both near‑hardware performance (critical for systems programming, game engines, embedded devices) and high‑level abstractions that improve developer productivity and code maintainability. The language has evolved through several ISO standards: C++98 (first standardized), C++03 (minor fixes), C++11 (a major revolution with move semantics, lambdas, auto), C++14, C++17, and C++20. Modern C++ (C++11 and later) emphasizes safety, expressiveness, and compile‑time computation.

According to the TIOBE index (January 2021 shown in lecture M01), C++ consistently ranks among the top 4 languages, often behind C, Java, and Python. Its applications span operating systems (Windows, Linux, macOS kernels), databases (MySQL, MongoDB), web browsers (Chrome, Firefox), game engines (Unreal Engine), and high‑frequency trading systems. The language's zero‑cost abstractions mean you don't pay for what you don't use – a key philosophy.

C++ is not just "C with classes". It introduces a stronger type system, references, namespaces, exceptions, templates (compile‑time polymorphism), and the Standard Template Library (STL). The STL provides generic containers (vector, map), algorithms (sort, find), and iterators that glue them together. This enables writing reusable, efficient code without sacrificing performance.

Learning C++ requires understanding both the high‑level features and the underlying memory model. This course (Programming in Modern C++) focuses on C++11/14/17 features and best practices, assuming basic C knowledge. The first week sets the stage by comparing C and C++ idioms, showcasing the ease and safety that C++ brings to tasks like I/O, string handling, and container management.

💻 Code Example – Checking Compiler C++ Version

Example: Determine C++ standard
#include <iostream>

int main() {
    if (__cplusplus == 201703L) std::cout << "C++17\n";
    else if (__cplusplus == 201402L) std::cout << "C++14\n";
    else if (__cplusplus == 201103L) std::cout << "C++11\n";
    else if (__cplusplus == 199711L) std::cout << "C++98\n";
    else std::cout << "pre-standard C++\n";
    return 0;
}

Output (typical for g++ -std=c++17): C++17

Explanation: The predefined macro __cplusplus holds the version of the C++ standard being used. This is essential for writing portable code that conditionally uses newer features.

🔑 Key Terminology

  • Zero‑cost abstraction – Language features that incur no runtime overhead compared to hand‑written low‑level code.
  • STL (Standard Template Library) – A collection of generic containers, algorithms, and iterators.
  • ISO C++ Standard – The official specification (e.g., ISO/IEC 14882:2017).
  • Multi‑paradigm – Supports procedural, object‑oriented, generic, and functional styles.

🧩 Common Misconceptions

Misconception: "C++ is just C with some extra features, so you can write C code and compile it with a C++ compiler without changes."
This is WRONG. While C++ is largely compatible with C, there are subtle differences: C++ has stricter type checking, different treatment of const, no implicit void* conversion, and requires function prototypes. Many C idioms (like using malloc without casting) fail in C++.
Misconception: "C++ is too complex and only for systems programming."
WRONG. Modern C++ (C++11 onward) is more accessible, with features like auto, range‑based for, and smart pointers that reduce boilerplate. It is used in a wide variety of domains, including desktop applications, web servers, and even machine learning (with libraries like TensorFlow).

⚠️ Edge Cases & Compiler Behavior

Edge Case: Mixing C and C++ headers
Including <math.h> in C++ places functions in the global namespace. The preferred C++ way is <cmath>, which places them in std:: and may offer overloads. Using deprecated .h C++ headers (e.g., <iostream.h>) is non‑standard and should be avoided.

📚 C++ Standard Reference

ISO/IEC 14882:2017 (C++17): §5.2 [lex.phases] – The predefined macro names. __cplusplus is defined in §16.8 [cpp.predefined].

🎯 Key Takeaways

  • C++ offers both high performance and high abstraction. It is the language of choice for performance‑critical, complex software.
  • Modern C++ (≥ C++11) is a different language from classic C++. Focus on smart pointers, lambdas, and STL algorithms.
  • Always know your compiler's standard version via __cplusplus.
  • C++ is not a strict superset of C – be aware of incompatibilities.
  • The STL is your best friend – learn it thoroughly.
M02 – Input/Output & Loops in C++

Concept 2.1 – std::cout, std::cin, and Stream I/O

C++ replaces C's printf/scanf with type‑safe stream objects: std::cout (standard output) and std::cin (standard input). The stream operators << (insertion) and >> (extraction) are overloaded for built‑in types and user‑defined types.

🧠 Encyclopedic Explanation

In C, I/O relies on variadic functions like printf and scanf that use format specifiers (%d, %s). This approach is error‑prone: mismatched specifiers lead to undefined behavior, and there is no type checking. C++ introduces a stream‑based I/O library defined in <iostream>. std::cout is an object of type std::ostream connected to the standard output. The operator << is overloaded for all fundamental types, so you simply write std::cout << 42;. The compiler deduces the correct formatting from the type of the expression.

Similarly, std::cin is an object of type std::istream. The extraction operator >> reads formatted input, skipping whitespace by default, and stores the value in the provided variable. It is type‑safe because the compiler knows the variable's type. Multiple values can be chained: std::cin >> a >> b;.

Another important manipulator is std::endl, which inserts a newline character ('\n') and flushes the output buffer. Flushing can be expensive, so in performance‑sensitive code, using '\n' alone is preferred unless immediate output is required.

The use of using namespace std; is common in tutorials to avoid writing std:: repeatedly. However, in header files and large projects, it's considered bad practice because it pollutes the global namespace. Prefer explicit qualification or using declarations (using std::cout;).

💻 Code Examples

Example 1: Basic I/O (C vs C++)
// C version
#include <stdio.h>

int main() {
    int a, b;
    printf("Enter two numbers: ");
    scanf("%d%d", &a, &b);
    printf("Sum = %d\n", a + b);
    return 0;
}

// C++ version
#include <iostream>

int main() {
    int a, b;
    std::cout << "Enter two numbers: ";
    std::cin >> a >> b;
    std::cout << "Sum = " << a + b << std::endl;
    return 0;
}

Output: (Input: 3 4) Sum = 7

Explanation: No format strings, no address‑of operator needed for cin (except for C‑strings). The type of a+b is deduced automatically.

Example 2: Chaining and Manipulators
#include <iostream>
#include <iomanip>   // for std::setw, std::setprecision

int main() {
    double pi = 3.1415926535;
    std::cout << "Default: " << pi << '\n';
    std::cout << "Precision 3: " << std::setprecision(3) << pi << '\n';
    std::cout << "Width 10: |" << std::setw(10) << 42 << "|\n";
    return 0;
}

Output: Default: 3.14159
Precision 3: 3.14
Width 10: | 42|

🔑 Key Terminology

  • Stream – An abstraction representing a sequence of bytes (input or output).
  • Manipulator – A function that modifies the stream's state, e.g., std::endl, std::setw.
  • Buffer flush – Forcing the output buffer to be written to the device.

🧩 Common Misconceptions

Misconception: "std::endl is just a newline character."
WRONG. std::endl inserts '\n' AND flushes the stream. Flushing can degrade performance. Use '\n' unless you explicitly need to flush (e.g., before waiting for user input).
Misconception: "cin >> reads the whole line."
WRONG. cin >> stops at whitespace. To read a whole line including spaces, use std::getline(std::cin, str).

⚠️ Edge Cases

Edge Case: Mixing cin >> and getline
After cin >> value, the newline remains in the input buffer. A subsequent getline will read an empty string. Solution: use cin.ignore() to discard the newline.

📚 C++ Standard Reference

ISO/IEC 14882:2017: §30.4 [iostream.objects] – Standard stream objects. §30.7 [ostream.manip] – Standard manipulators.

🎯 Key Takeaways

  • Prefer C++ streams over printf/scanf for type safety and extensibility.
  • Use '\n' for newline, std::endl only when flush is needed.
  • Avoid using namespace std; in headers.
  • Be mindful of input buffer leftovers when mixing >> and getline.

Concept 2.2 – Variable Declaration Anywhere and the bool Type

Unlike C89, C++ allows variables to be declared at any point in a block, not just at the beginning. C++ also provides a built‑in Boolean type bool with literals true and false.

🧠 Explanation

In C89, all local variables must be declared at the start of a block. This restriction can lead to variables being declared far from their first use, reducing readability. C++ (and C99) allow declarations anywhere. This enables better scoping and initialization at the point of first use, which is a cornerstone of modern C++ style (RAII).

The bool type was absent in early C. Programmers used int with 0 for false and non‑zero for true, or macros like #define TRUE 1. C++ introduces bool as a distinct type, which improves type safety and code clarity. The keywords true and false are literals of type bool. When converted to an integer, true becomes 1 and false becomes 0.

💻 Code Example

Example: bool and declaration anywhere
#include <iostream>

int main() {
    bool a = false, b = true, c = true;
    std::cout << (a && b || c) << '\n';   // output: 1 (true)

    for (int i = 0; i < 3; ++i) {   // 'i' declared in loop header (C++ only)
        int square = i * i;         // declared inside loop
        std::cout << i << "^2 = " << square << '\n';
    }
    // 'square' not accessible here
    return 0;
}

Output: 1
0^2 = 0
1^2 = 1
2^2 = 4

🧩 Misconception

Misconception: "bool in C++ is just an alias for int."
WRONG. bool is a distinct type. Overload resolution treats it separately, and sizeof(bool) is implementation‑defined (often 1 byte). The conversion to int is defined, but it is not an int.

🎯 Takeaway

Declare variables as close to first use as possible, and use bool for logical flags.

M03 – Arrays and Strings

Concept 3.1 – Fixed‑size Arrays vs std::vector

C‑style fixed‑size arrays have static size known at compile time. std::vector is a dynamic array that can grow or shrink at runtime, managing memory automatically.

🧠 Encyclopedic Explanation

In C, arrays are often declared with a constant size, e.g., int arr[100];. If the actual number of elements needed is smaller, memory is wasted. If it exceeds 100, buffer overflow occurs. C programmers use malloc/free for dynamic arrays, which is error‑prone (forgetting to free, memory leaks). C++ provides std::vector in <vector>, a template class that encapsulates a dynamic array. It manages memory automatically (RAII) and provides member functions like push_back, size, and resize.

Vectors store elements contiguously, so pointer arithmetic works. They also provide bounds checking with .at() (throws std::out_of_range), while operator[] does not check bounds (for performance). The capacity of a vector can be larger than its size; reserve() can preallocate memory to avoid reallocations.

💻 Code Examples

Example 1: C fixed array vs C++ vector
// C with macro
#include <stdio.h>

#define MAX 100

int main() {
    int arr[MAX], n = 5;
    for(int i=0; i<n; i++) arr[i]=i;
    printf("Sum = %d\n", arr[0]+arr[1]); // 1
    return 0;
}

// C++ with vector
#include <iostream>
#include <vector>

int main() {
    std::vector<int> arr;
    int n = 5;
    for(int i=0; i<n; i++) arr.push_back(i);
    std::cout << "Sum = " << arr[0]+arr[1] << '\n';
    return 0;
}

Output: Sum = 1

Example 2: Vector resizing and capacity
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v(3, 10); // size 3, all 10
    v.push_back(20);
    std::cout << "size: " << v.size() << ", capacity: " << v.capacity() << '\n';
    v.resize(10, 99); // size becomes 10, new elements = 99
    v.resize(5);      // size becomes 5, extra elements destroyed
    return 0;
}

Output (typical): size: 4, capacity: 6 (or 8)
Then vector contains [10,10,10,20,99...].

🧩 Misconceptions

Misconception: "vector::resize(n) changes capacity to n."
WRONG. resize() changes the size, not necessarily the capacity. Capacity remains unchanged or may increase if needed. Use reserve() to influence capacity.
Misconception: "vector elements are always default‑initialized."
WRONG. When you resize larger, new elements are value‑initialized (zero for ints). If you use the two‑parameter constructor vector<int> v(5, 42), all elements are 42.

⚠️ Edge Cases

Edge Case: Iterator/pointer invalidation
If a vector reallocates (e.g., push_back when size==capacity), all iterators, pointers, and references to elements become invalid. Always be cautious when storing pointers to vector elements.

🎯 Key Takeaways

  • Prefer std::vector over C arrays for dynamic sizing and safety.
  • Use reserve() to avoid reallocations in performance‑critical loops.
  • Be aware of iterator invalidation on reallocation.

Concept 3.2 – C‑Strings vs std::string

C‑strings are null‑terminated character arrays (char*). std::string is a class that manages a dynamic string, providing concatenation, comparison, and many utility functions.

🧠 Explanation

Manipulating C‑strings requires functions like strcpy, strcat, strlen, which are error‑prone (buffer overruns). C++ std::string overloads operators (+ for concatenation, ==, < for comparison) and provides member functions like .length(), .substr(), .find(). Memory management is automatic.

💻 Code Example – Concatenation

C vs C++ string concatenation
// C version
char str1[20] = "Hello ";
char str2[] = "World";
char result[40];
strcpy(result, str1);
strcat(result, str2);
printf("%s\n", result);

// C++ version
std::string s1 = "Hello ";
std::string s2 = "World";
std::string result = s1 + s2;
std::cout << result << '\n';

Output: Hello World

🔑 Key Functions (std::string)

Function Description C equivalent
+ / += Concatenation strcat
==, !=, <, > Comparison strcmp
.length() / .size() Length strlen
.substr(pos, count) Substring manual copying
.find(str) Search strstr

🧩 Misconception

Misconception: "std::string can be passed to functions expecting const char* directly."
WRONG. Use .c_str() to obtain a const C‑string. Note that the pointer may be invalidated if the string is modified.

⚠️ Edge Case

Edge Case: Small String Optimization (SSO)
Many implementations store short strings directly inside the string object (no heap allocation). This affects iterator invalidation – swapping two strings may not invalidate pointers.

🎯 Takeaway

Use std::string for all text manipulation in C++. It is safer, more convenient, and often as efficient as C‑strings.

M04 – Sorting and Searching with STL Algorithms

Concept 4.1 – std::sort and Custom Comparators

std::sort(begin, end, comp) sorts elements in the range [begin, end). Without a comparator, it sorts in ascending order using operator<. A custom comparator can be a function, function object, or lambda that defines strict weak ordering.

🧠 Explanation

The STL sort algorithm (in <algorithm>) is typically an introsort hybrid (quicksort + heapsort) guaranteeing O(N log N) complexity. It works on random‑access iterators (e.g., arrays, vectors, deques). The comparator must return true if the first argument should go before the second. It must enforce strict weak ordering (irreflexive, transitive, antisymmetric).

💻 Code Examples

Example 1: Default ascending sort
#include <iostream>
#include <algorithm>

int main() {
    int data[] = {32, 71, 12, 45, 26};
    std::sort(data, data + 5);
    for(int x : data) std::cout << x << ' ';
    return 0;
}

Output: 12 26 32 45 71

Example 2: Descending with lambda (C++11)
#include <iostream>
#include <algorithm>
#include <vector>

int main() {
    std::vector<int> v = {32, 71, 12, 45, 26};
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
    for(int x : v) std::cout << x << ' ';
    return 0;
}

Output: 71 45 32 26 12

Example 3: Sorting part of a range
int data[] = {50, 30, 40, 10, 20};
std::sort(&data[2], &data[4]);   // sorts elements at indices 2 and 3
// data becomes {50, 30, 10, 40, 20}

🧩 Misconceptions

Misconception: "The comparator should return true for equal elements."
WRONG. It must return false for equal elements; otherwise the algorithm may crash or produce incorrect results (strict weak ordering violation).
Misconception: "std::sort is stable."
WRONG. std::sort does not guarantee stability. Use std::stable_sort if you need to preserve relative order of equivalent elements.

⚠️ Edge Cases

Edge Case: Sorting an empty range or single element
std::sort works fine; nothing happens. However, passing invalid iterators (e.g., end before begin) leads to undefined behavior.

📚 Standard Reference

§28.7.1 [alg.sort] – Sorting and related operations.

🎯 Takeaways

  • Use std::sort for efficient O(N log N) sorting.
  • Lambda comparators are concise and flexible.
  • Remember strict weak ordering: comparator(a,a) must be false.

Concept 4.2 – std::binary_search, std::lexicographical_compare, std::rotate, std::replace

STL provides many ready‑to‑use algorithms. binary_search checks if a value exists in a sorted range. lexicographical_compare compares two sequences lexicographically. rotate shifts elements, and replace substitutes values.

🧠 Explanation

binary_search: Requires the range to be sorted. Returns true if the value is present, false otherwise. It uses operator< by default or a custom comparator. The range is [first, last).

lexicographical_compare: Compares two sequences element by element. Returns true if the first sequence is lexicographically less than the second. This is the algorithm used by std::string's operator<.

rotate: Performs a left rotation on a range. rotate(first, middle, last) makes middle the new first element. Useful for array rotations.

replace: Replaces all occurrences of a value in a range with another value.

💻 Code Examples from Assignments

Problem 01: lexicographical_compare with case‑insensitive comparator
#include <iostream>
#include <algorithm>
#include <cstring>

bool compare(char c1, char c2) {
    return tolower(c1) < tolower(c2);
}

int main() {
    char arr1[20] = "C++ Course", arr2[20] = "C Course";
    std::cout << std::lexicographical_compare(arr1, arr1+strlen(arr1),
                                                arr2, arr2+strlen(arr2), compare);
    return 0;
}

Output: 0 (false) because "C++ Course" is not lexicographically less than "C Course" under case‑insensitive compare.

Problem 02: binary_search range
int array[] = {1, 2, 3, 4, 5};
int key = 5;

// To print "not found", we must exclude the last element:
if(binary_search(array, array+4, key)) // searches [1,2,3,4] – 5 not found
    std::cout << "found";
else
    std::cout << "not found";

Output: not found

Problem 03: rotate
std::vector<int> arr = {1, 2, 3, 4, 5, 6, 7};
std::rotate(arr.begin(), arr.begin()+2, arr.begin()+4);
// Rotates subrange [1,2,3,4] left by 2: becomes [3,4,1,2]
// Full array: 3 4 1 2 5 6 7
Problem 08: replace
int arr[] = {1, 2, 3, 4, 5};
for(int i=0; i<1; i++) {
    int j = arr[i];
    std::replace(arr, arr+5, j, *(arr + 4 - i));
}
// i=0: j=1, replace all 1's with arr[4] = 5 → arr = {5,2,3,4,5}

🧩 Misconceptions

Misconception: "binary_search returns the index of the found element."
WRONG. It returns bool. Use std::lower_bound to get an iterator to the first position where the element could be inserted.
Misconception: "rotate works only on the whole container."
WRONG. It works on any iterator range. The example shows rotating a sub‑vector.

🎯 Takeaways

  • STL algorithms are generic and work with any container providing iterators.
  • Always ensure ranges are valid and sorted for binary search.
  • Custom comparators allow flexible ordering.
M05 – Stack and Containers

Concept 5.1 – C‑Style Stack Implementation vs std::stack

In C, a stack is manually implemented using an array and a top index. C++ provides std::stack (a container adaptor) that encapsulates a LIFO data structure, using any underlying container (default std::deque).

🧠 Explanation

A stack is a fundamental data structure with push, pop, and top operations. In C, you define a struct, manage an array, and write functions. This code is tied to a specific element type. C++ std::stack<T> is a template adaptor that wraps a container (like vector, deque, list) and provides the stack interface: push(), pop(), top(), empty(), size(). It eliminates manual memory management and works for any type.

💻 Code Example – Reverse a String

C version (manual stack)
typedef struct { char data[100]; int top; } stack;

void push(stack *s, char c) { s->data[++(s->top)] = c; }
// ... pop, top, empty ...

int main() {
    char str[] = "ABCDE";
    stack s; s.top = -1;
    for(int i=0; i<strlen(str); i++) push(&s, str[i]);
    while(!empty(&s)) { printf("%c", top(&s)); pop(&s); }
}

Output: EDCBA

C++ version (std::stack)
#include <iostream>
#include <stack>

int main() {
    std::string str = "ABCDE";
    std::stack<char> s;
    for(char c : str) s.push(c);
    while(!s.empty()) { std::cout << s.top(); s.pop(); }
}

Output: EDCBA

🔑 Key Terminology

  • Container adaptor – A class that provides a restricted interface to an underlying container (e.g., stack, queue, priority_queue).
  • Underlying container – The actual container used by the adaptor (must support back(), push_back(), pop_back()).

🧩 Misconceptions

Misconception: "std::stack::pop() returns the top element."
WRONG. pop() returns void. You must call top() to get the element before popping. This design avoids exception‑safety issues.
Misconception: "std::stack can be iterated like a vector."
WRONG. Stack does not provide iterators. To access all elements, you must pop them (destructive) or use the underlying container via a protected member (not recommended).

⚠️ Edge Cases

Edge Case: Calling top() or pop() on an empty stack
Undefined behavior. Always check !s.empty() first.

📚 Standard Reference

§24.6.5 [stack] – Class template stack.

🎯 Takeaways

  • Use std::stack for LIFO behavior; it's safe and generic.
  • Remember top() then pop(); pop() does not return the value.
  • STL containers (vector, list, deque, map, etc.) are essential building blocks.

Concept 5.2 – Introduction to STL Containers (Overview)

The STL provides sequence containers (vector, deque, list, array, forward_list), associative containers (set, map, multiset, multimap), unordered associative containers (unordered_set, unordered_map), and container adaptors (stack, queue, priority_queue).

🧠 Explanation

Each container has different performance characteristics and guarantees. Choosing the right container is crucial for efficient programs. For example, vector provides fast random access and amortized O(1) push_back, but insertions in the middle are O(n). list provides O(1) insertions anywhere but no random access. set/map are typically red‑black trees with O(log n) operations. unordered_set/unordered_map use hash tables with average O(1) lookup.

In this course, we will explore containers in depth later, but Week 01 introduces the concept of ready‑made data structures.

📊 Container Summary

Container Header Key Feature
vector <vector> Dynamic array, contiguous memory
deque <deque> Double‑ended queue, fast insert at both ends
list <list> Doubly linked list
forward_list <forward_list> Singly linked list (C++11)
set / map <set> / <map> Ordered unique keys / key‑value pairs
unordered_set / map <unordered_set> / <unordered_map> Hash table based (C++11)
stack / queue / priority_queue <stack> / <queue> Adaptors providing LIFO / FIFO / priority

🎯 Takeaway

Know the basic containers and their trade‑offs. The STL is your toolbox for data management.
